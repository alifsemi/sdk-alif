PWM Test Suite
==============

Overview
********

This test suite validates the Alif PWM driver using the Zephyr Ztest
framework. PWM is generated by the Alif UTIMER IP: the first 12 UTIMER
channels can each produce 2 PWM outputs (24 signals total). Each UTIMER
instance has 2 compare blocks dedicated to PWM generation.

Two applications are provided:

- ``pwm_api`` — Zephyr PWM API coverage, polarity, channels, duty-cycle
  sweeps, and the fade-LED / blinky sample flows.
- ``pwm_loopback`` — PWM capture (pulse, period, continuous, timeout,
  busy). Capture cases skip when the driver returns ``-ENOTSUP`` or
  ``-ENOSYS``.

The tests require a ``pwm-led0`` (API) or ``pwm-led6`` / ``pwm-led7``
(loopback) alias from a board overlay. Use a multimeter or scope on the
mapped PWM pin to confirm duty cycle and polarity when measuring output.

Configuration
*************

``pwm_api/prj.conf``:

- ``CONFIG_PWM=y``
- ``CONFIG_ZTEST=y``

``pwm_loopback/prj.conf``:

- ``CONFIG_PWM=y``
- ``CONFIG_PWM_CAPTURE=y``
- ``CONFIG_ZTEST=y``

CMake options (``pwm_api``):

- ``INVERTED=ON`` — select the inverted-polarity overlay
- ``OSPI=ON`` — apply the board OSPI pinctrl overlay

CMake options (``pwm_loopback``):

- ``MRAM=ON`` — include the board MRAM pinctrl overlay
- ``OSPI=ON`` — include the board OSPI pinctrl overlay

Building and Running
********************

Select the target board as described in the ZAS User Guide. Pass the
matching overlay with ``-DDTC_OVERLAY_FILE``.

PWM API — Ensemble, normal polarity
-----------------------------------

.. code-block:: console

   west build -p always -b <board> tests/drivers/pwm/pwm_api \
     -DDTC_OVERLAY_FILE=boards/alif_ensemble_pwm_normal.overlay

PWM API — Ensemble, inverted polarity
-------------------------------------

.. code-block:: console

   west build -p always -b <board> tests/drivers/pwm/pwm_api \
     -DDTC_OVERLAY_FILE=boards/alif_ensemble_pwm_inverted.overlay

PWM API — Balletto, normal polarity
-----------------------------------

.. code-block:: console

   west build -p always -b <board> tests/drivers/pwm/pwm_api \
     -DDTC_OVERLAY_FILE=boards/alif_balletto_pwm_normal.overlay

PWM loopback
------------

.. code-block:: console

   west build -p always -b <board> tests/drivers/pwm/pwm_loopback \
     -DDTC_OVERLAY_FILE=boards/alif_pwm.overlay

Flash after a successful build:

.. code-block:: console

   west flash

Test Suites
***********

``pwm_api``
-----------

``pwm_basic_api`` (``src/test_pwm.c``):

- ``different_duty_cycle_pulse_test`` — 25%, 100%, 50%, and 0% duty via
  ``pwm_set_dt`` (nsec).
- ``z_max_period_test`` — large period / pulse (4 s / 1 s nsec).

``pwm_basic`` (``src/test_pwm_cycles.c``):

- Device ready and ``pwm_get_cycles_per_sec``
- Invalid channel returns ``-EINVAL``
- Channel 0, channel 1, and both channels together
- ``pwm_set`` / ``pwm_set_cycles`` in nsec and cycles
- Normal and inverted polarity, polarity switch
- Zero period / zero pulse disable, zero pulse + inverted
- Period and pulse updates while running
- Duty-cycle sweep (0–100%) and 100% duty
- Small period/pulse and pulse greater than period
- ``pwm_set_dt``, ``pwm_set_pulse_dt``, ``pwm_is_ready_dt``
- Rapid reconfigure and enable/disable stress

``fade_led`` (``src/fade_led.c``):

- ``test_pwm_fade_led_app`` — ramps pulse width up and down (sample
  fade-LED flow).

``pwm_blinky`` (``src/blink_pwm.c``):

- ``test_blinky_pwm_app`` — calibrates max period, then blinks at
  changing frequencies (sample blinky-PWM flow).

``pwm_loopback``
----------------

Suite ``pwm_loopback`` (``src/test_pwm_loopback.c``):

- Pulse capture (normal and inverted), nsec and usec
- Period capture (normal and inverted), nsec and usec
- Combined pulse and period capture
- Capture timeout (``-EAGAIN``)
- Continuous capture callback
- Capture busy (``-EBUSY`` while enabled)

Cases that need capture skip if the driver does not implement it.

Expected Output
***************

Duty-cycle tests set period and pulse so a DC measurement on the PWM pin
is approximately:

- Period : Pulse (1 : 1) — always on (rail)
- Period : Pulse (2 : 1) — half rail
- Period : Pulse (1 : 0) — always off (0 V)

Actual voltage depends on the pad and LED path (for example 1.8 V vs
3.3 V). Invert polarity with the inverted overlays or
``PWM_POLARITY_INVERTED``.

Fade-LED and blinky tests print the same style of messages as the Zephyr
samples (pulse-width percent steps and calibrated period values).

Notes
*****

- Hardware is required; simulation is not supported.
- Overlay files live under each test’s ``boards/`` directory. Pass them
  with ``-DDTC_OVERLAY_FILE`` when the CMake ``BOARD`` name does not
  match ``alif_ensemble`` or ``alif_balletto``.
- Related application note: ``doc/appnotes/source/pwm.rst``.
